# 家庭日历（Family Calendar）· 产品设计方案

> 部署目标：华为 Mate9（Termux）家庭服务器
> 定位：局域网内家庭共用的日历与待办，覆盖一次性事项与周期性家务
> 状态：M1 / M2 / M2.5 / M3 / M4 已实现并部署到 mate9:8081

## 1. 目标与边界

一句话：让家里人打开一个网页，就知道「接下来要做什么」，周期性家务不用靠记。

**要解决的真实痛点**

- 一次性事项容易忘（报修家电、缴费、取快递、孩子活动）
- 周期性家务没有载体（每两周换床单、每月洗滤网、每季度体检）
- 现有日历 App 偏重日程，不擅长「做完打勾、下个周期自动再来」

**明确不做（v1）**

- 不做 PWA、Service Worker、桌面/系统通知（已确认放弃，避免 HTTPS 与证书成本）
- 不做密码登录、权限隔离（身份仅用于区分「谁负责」）
- 不做与外部日历（iCloud / 飞书）的双向同步
- 不做农历、节假日调休
- 不做公网访问

**已知取舍**：没有系统通知，提醒只在你打开页面时可见。因此界面必须做到「一进来就知道今天还剩什么」，而不是依赖弹窗。

## 2. 用户与场景

家庭内 2–4 个成员，通过手机浏览器直接访问网页（页面不发安装提示，也不做离线缓存）。

**身份模型**：不预设任何角色。首次打开时输入自己的名字，名字即身份（同名不区分大小写复用），落库并记在本机 localStorage。不支持切换身份，只能使用自己的身份；只能「改自己的名字」或「清除本机身份后重新输入」。身份用于事项归属、颜色区分和「我的待办」筛选，不承担安全职责。

**写权限约束**：有身份才能新增 / 编辑 / 删除事项、标记完成 / 跳过 / 撤销；未输入名字时只能浏览。未登录点写操作会先唤起输入名字；服务端写接口强制要求 `x-member-id` 头，缺失或失效返回 401，改名只能改自己（403）。

| 场景 | 行为 |
|---|---|
| 日常查看 | 打开网页，首页直接显示「今日 N 项」与未完成清单 |
| 新增事项 | 点「+」，选日期、写标题、选「一次性 / 重复」，勾选负责成员（可多选） |
| 周期家务 | 设「每 2 周」，勾选完成后自动滚动到下一次 |
| 临时变化 | 这周不做 → 「跳过本次」；改期 → 「仅改这一次」 |
| 逾期 | 过期未完成的事项在首页顶部聚集并标红，不会沉到日历里被忽略 |

## 3. 核心概念

| 概念 | 说明 |
|---|---|
| 事项 Event | 一条待办的「定义」，含标题、重复规则、负责成员（可多个） |
| 实例 Occurrence | 由重复规则展开出的某一天的具体待办（虚拟，不落库） |
| 完成记录 Completion | 对某个实例的「已完成 / 已跳过」，按 `(event_id, 日期)` 落库 |
| 成员 Member | 用户首次使用时输入的名字，无密码；同名复用，不预设角色 |

**成员与完成语义**：事项成员为多选，可同时指派多人；不选成员即「全家共用」。完成状态是事项级的整体完成，任一人标记即完成，不按成员分别记录。月历用成员颜色渐变条区分，列表显示成员名字。

**关键设计**：不预生成未来所有实例，只在查询区间内按规则展开；完成状态用稀疏记录覆盖在展开结果上。这样「每两周换床单」永远只有一条 Event 和若干条 Completion，不会随年份膨胀。

## 4. 功能清单

### MVP

- 月历视图：格子内显示事项（最多 2 条 + 「还有 N 项」）
- 今日清单：按时间排序，勾选完成，支持「我的待办」筛选
- 逾期区：未完成且已过期的实例单独聚合在首页顶部
- 新增 / 编辑 / 删除事项，成员可多选（不选即全家）
- 重复规则：不重复、每天、每周、每两周、每月同日、每年同日
- 完成 / 跳过本次 / 撤销完成
- 提醒（应用内）：`document.title` 前缀未完成数、首页红点、今日数量角标
- 首次进入输入名字即完成登录；头像面板可改名或清除本机身份
- 未登录只能查看，写操作会先唤起输入名字
- 移动端优先布局

### 后续

- 周视图、拖拽改期
- 「仅改这一次」与「改此后所有」
- 每周多选（每周一、周四）与更复杂的 RRULE
- 完成统计（本月完成率、连续完成天数）
- 搜索与筛选、数据导出 / 导入
- 可选增强：改用 Termux 通知或接入 HTTPS 后再补系统级提醒

## 5. 重复规则

对外只暴露 6 个选项，内部用二元组表达：

| UI 选项 | freq | interval |
|---|---|---|
| 不重复 | `none` | — |
| 每天 | `daily` | 1 |
| 每周 | `weekly` | 1 |
| 每两周 | `weekly` | 2 |
| 每月同日 | `monthly` | 1 |
| 每年同日 | `yearly` | 1 |

附加字段：`startDate`（起点）、`endDate`（可选）。展开时从 `startDate` 按间隔步进，`monthly` 遇 31 号在小月自动退到月末（31 → 30/28）。采用全 UTC 的自研展开函数（`server/utils/recurrence.ts`），未引入 rrule，以便精确控制月末回退行为。

## 6. 提醒设计（仅应用内）

没有系统通知，所以提醒做在「进入页面的第一屏」：

1. **标题计数**：`(3) 家庭日历`，未完成今日事项数直接写进 `document.title`，切到其他标签页也能看到
2. **首页逾期区**：过期未完成的事项置顶标红，附「已逾期 N 天」
3. **今日角标**：底部导航「今日」入口上显示未完成数量徽标
4. **日历格标记**：有未完成事项的日期显示实心点，全部完成显示空心点

设计原则：不打断，但绝不隐藏。用户只要打开页面，剩余待办就在视线内。

## 7. 页面结构

```
/                首页（月历 + 当日清单）
/event/new       新建
/event/[id]      编辑
```

单页结构。身份入口在首页右上角头像：未登录时显示「登录」，点击弹出输入名字；已登录显示首字头像，点击进入账号面板（改名 / 清除本机身份）。首次访问自动弹「你叫什么名字？」。

## 8. 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Nuxt 4（Nitro） | 一体化前后端，API 与查询逻辑同进程 |
| 渲染 | `ssr: false`（SPA）+ Nitro API | 内网无 SEO 需求，省内存、少水合坑 |
| 样式 | Tailwind CSS v4 | 与 monitor 项目一致 |
| 数据库 | SQLite，Node 内置 `node:sqlite` | 零原生依赖，单文件易备份 |
| 日期/重复 | dayjs + 自研展开 | 纯 JS，Termux 兼容，月末回退可控 |
| 进程 | pm2（`--max-memory-restart 300M`） | 与现有服务同一套运维 |
| 访问 | 直接访问 `http://192.168.31.234:8081` | 不引入 HTTPS、不经过 Caddy |

**部署方式**：Mac 上 `nuxt build`（preset `node-server`）→ `rsync .output/` 到 `~/family-calendar` → pm2 启动 `.output/server/index.mjs`。手机上不运行构建。`backup.mjs` 随发布上传，由 pm2 cron 每日执行。

**不引入**：sharp / nuxt-image（Bionic 无预编译）、任何原生扩展、web-push、Service Worker。

### 数据模型

```sql
member(id, name, color, created_at)          -- name 唯一（NOCASE）

event(
  id, title, note,
  all_day, start_time,
  freq, interval, start_date, end_date,
  created_at, updated_at, archived
)

event_member(event_id, member_id)            -- 多对多；无记录 = 全家共用
PRIMARY KEY(event_id, member_id)

occurrence_state(                            -- 稀疏覆盖层
  id, event_id, date,                        -- YYYY-MM-DD
  state,                                     -- done | skipped
  completed_at
)
UNIQUE(event_id, date)
```

索引：`event(start_date)`、`occurrence_state(event_id, date)`、`event_member(member_id)`、`member(name COLLATE NOCASE)`。

旧库（v0：`event.member_id` + `member.emoji`）在启动时自动迁移：把单成员关系转入 `event_member`，删除未被任何事项引用的预设成员，移除 `emoji` 列，`PRAGMA user_version` 升到 1。

### API 草案

```
GET    /api/events?from=&to=&member=   -- member 过滤：包含该成员 或 无成员（全家）
POST   /api/events                     -- 写操作需 x-member-id
PATCH  /api/events/:id
DELETE /api/events/:id
POST   /api/occurrences/:eventId/:date/complete | /skip | /undo
GET    /api/today?member=
GET    /api/members                    -- 已输入过名字的成员
POST   /api/members                    -- { name } 输入名字，同名复用
PATCH  /api/members/:id                -- 只能改自己
```

写接口（events 的 POST/PATCH/DELETE、occurrences、members 的 PATCH）统一校验 `x-member-id`：缺失返回 401「请先输入你的名字」，成员不存在返回 401，越权改名返回 403。前端通过 `useApi()` 自动附加该头。

## 9. 非功能要求

- 内存：常驻 < 200 MB（无推送、无 SW，仅有 Nitro + SQLite）
- 首屏：局域网内 < 1 s
- 可用性：手机重启后由 Termux:Boot + pm2 自动恢复
- 数据安全：SQLite 单文件，每日 03:30 备份到 `~/backup/`，保留最近 7 份（`backup.mjs`，pm2 定时任务）
- 时间：统一按设备本地时区（Asia/Shanghai），不做跨时区
- 浏览器兼容：Android Chrome / iOS Safari 近两年版本，不使用实验性 API

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 骨架 | Nuxt 工程、SQLite 表、事项 CRUD、月历只读 | 能在手机增删事项并在月历看到 |
| M2 重复 | 规则展开、完成/跳过、今日清单、身份选择 | 「每两周换床单」正确出现在未来各周 |
| M2.5 身份 | 去掉预设角色、输入名字即身份、服务端写接口校验、成员多选 | 首次输入名字后可增删改；未登录只能查看；多人负责的事项显示多个成员 |
| M3 提醒 | 首页逾期区、标题计数、角标、日历格状态点 | 打开页面一眼能看到今天剩什么、逾期什么 |
| M4 打磨 | 每日备份、空状态、错误重试、无障碍与键盘操作 | 数据可恢复，首屏在手机上不溢出 |

## 11. 风险与限制

- **提醒只在打开页面时可见**：这是放弃系统通知后的固有代价。缓解手段是第一屏信息密度与标题计数，若日后觉得不够，可低成本补 Termux 通知。
- **后台存活**：鸿蒙杀进程会导致网页打不开。依赖 Termux 唤醒锁 + 电池白名单（现网已配置），pm2 开机 resurrect。
- **无鉴权**：身份只是「名字 + 本机记录」，不是权限控制。知道别人名字即可用其身份操作，服务端 `x-member-id` 校验只防止匿名写入，不防冒充。家庭场景可接受；路由器不要把 8081 映射到公网。
- **重复规则边界**：月末、闰年由自研展开函数处理，需补单元测试。
- **多设备身份**：localStorage 按浏览器隔离，换手机或清缓存后重新输入同名即可恢复原身份与颜色（不影响数据）。

## 12. 已确认的决策

| # | 决策 |
|---|---|
| 1 | 不做 PWA，纯网页应用，浏览器直接打开 |
| 2 | 提醒只做应用内提示（首页逾期区、标题计数、角标），不做系统通知 |
| 3 | 不预设角色；首次打开输入名字即身份，名字落库、同名复用，不支持切换身份 |
| 4 | 重复规则只做常用预设（不重复/每天/每周/每两周/每月/每年） |
| 5 | 应用独立端口 8081，直接 HTTP 访问，不引入 HTTPS 与 Caddy 反代 |
| 6 | 渲染模式 `ssr: false`，Nitro 只承担 API |
| 7 | 事项成员改为多选；不选成员 = 全家共用 |
| 8 | 无身份只能查看；写接口强制校验 `x-member-id`（401/403），未登录点写操作先唤起输入名字 |
| 9 | 完成状态为事项级整体完成，任一人可标记，不按成员分别记录 |
